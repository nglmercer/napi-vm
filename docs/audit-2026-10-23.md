# Reliability and performance audit — 2026-10-23

Base: `e2b1cd6ad98378df9c6b584a3e00b6a8b01e7d42` (`main`).

## Scope

Reviewed VM parser/cache and heap ownership, runtime permissions and socket I/O,
legacy TypeScript capabilities, trusted-process host/SDK/protocol, and editor
session transport. Ran the engine and plugin suites described below. This is a
source and regression audit on Linux x64, not a complete ECMAScript conformance
certification or a benchmark of Windows, Android/Termux, native addons and WASM.

## Confirmed findings and fixes

| Finding | Impact | Fix and evidence |
| --- | --- | --- |
| Host main-flag changes left cached import.meta stale | Calling setImportMetaMain after evaluation returned the previous value | Update the cached object in place and preserve identity and custom fields; Rust regression and existing Node/Bun cases |
| Dense indexed appends built and scanned a full presence bitmap | Repeated array growth was quadratic | Append without introducing a hole bitmap; dense/holey/sparse regression plus existing array suites |
| IPC depth negotiation did not update the decoder | A remote peer could exceed the agreed nesting limit | Update byte and depth limits together; regression sends an over-depth frame after negotiation |
| Coalesced TCP frames were all decoded before dispatch | Following frames used obsolete limits even when an earlier frame tightened them | Dispatch each completed frame before decoding the next; same-chunk byte/depth regressions |
| Runtime discovery used two synchronous child probes per candidate | Plugin loading could block the host event loop for up to two 5-second probe timeouts per candidate | Bounded asynchronous `execFile`; a delayed fake runtime reproduces the stall before the fix and permits host timer progress after it |
| Shutdown could complete while load was still in preflight | A child could start after shutdown returned | Recheck closing after preflight and before starting; deterministic race regression |
| JS error truncation split surrogate pairs | A valid Unicode error could fail wire encoding and disconnect the peer | Truncate by Unicode scalar, preserving the schema's 2048-character limit; sender and receiver regressions |
| Rust error messages used a different limit | Rust errors could disconnect JS peers instead of reaching callers | Use 2048 Unicode characters in both implementations |
| Rust accepted malformed error metadata | Unknown/mismatched stable codes, extra metadata and malformed application errors were accepted unlike JS | Validate numeric/stable code agreement, field set, message length and application data; Rust negative cases |
| Editor sessions retained exit listeners after stop | Repeated sessions remained reachable and emitted listener-leak warnings | Register on start, remove on stop, restore on restart; lifecycle regressions |
| Editor output lacked a pending-write cap | A connected client that stopped reading could retain unbounded snapshots | Enforce a 1 MiB per-client queued-write budget, including newline; slow-reader regression |
| Editor broadcast cloned/encoded the same snapshot per client | Maximum client fan-out caused 16 snapshot builds per update | Encode once and share the immutable frame; test verifies one snapshot for 16 clients |
| Host event size calculation repeated per subscriber | Large payloads were serialized up to twice per matching subscriber | Calculate the validated payload size once per event |
| String schema validation materialized a scalar array | A large string caused an avoidable allocation proportional to input size | Count scalars without building an array, stop early on maxLength, skip counting when no bounds apply |
| UTF-16 AST regression harness used the raw sequencer | Two existing tests failed before exercising their intended assertions because functions were never hoisted | Use documented `run_program_body`; all 17 UTF-16 tests pass |

New JS protocol, runtime-probe and editor regression cases were run against the
original implementation first and reproduced the failures. The Rust metadata
checks include direct invalid/valid error cases.

A local diagnostic of 20,000 direct indexed appends took approximately 1.16 s
before the dense append fix and 1.57 ms after it in the unoptimized `ci` profile.
These are single-run micro timings on this host, not an application-wide speedup
claim. The regression checks values, holes and sparse growth without a timing
assertion.

The existing asynchronous reentry test spent almost its entire 2-second deadline
on an unrelated 100,000-iteration guest loop (about 1.79 s standalone on this
host). Its admission reservation already exists synchronously before the callback
is released. Reducing the loop to 1,000 retains the queued-admission scenario and
removes that CPU-speed dependency without raising the deadline.

The CLI's vendored Rust SDK/protocol assets were regenerated using the canonical
sync script. This also removes existing source/template drift so newly generated
plugins use the audited implementations.

The full Bun run also exposed stale assertions that contradicted implemented
semantics: sloppy Annex B block functions, implemented Intl formatters, binary16
rounding, Date default coercion, sparse array storage, missing iterators, duplicate
JSON keys and the specified toFixed precision range. The tests now check those
behaviors explicitly. Object.assign's property-limit test previously used a JSON
object containing repeated copies of the same key, so it never filled the quota;
a Rust test now constructs the actual distinct-property limit and verifies the
next Object.assign insertion fails.

## Limits and further work

The fixes enforce existing protocol and resource policies; trusted-process plugins
remain trusted processes. Slow editor clients are disconnected at the output
budget and must reconnect. Runtime probes still execute on each preflight to
avoid stale executable/version decisions, but no longer block other host work.

Windows named-pipe behavior, Termux, WASM, and a full Test262 or native-addon
compatibility matrix were not exercised. Review of a subsystem does not imply
that every path was dynamically tested. Remaining profiling candidates include
synchronous editor locator writes, per-byte log-secret matching, and the runtime
HTTP server's byte-at-a-time header reads; no unmeasured speedup is claimed for
those paths.
